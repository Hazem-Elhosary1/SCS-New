# كود الرصيد الإضافي (Top-ups) في لوحة المشغلين

**التاريخ:** 28 سبتمبر 2026 · **المصدر:** تصميم ملف المشغلين بعد مراجعتيه، وهو المرجع:
- العيادات §13؛
- الباقات §6؛
- التذاكر §6؛
- المشغلون §4؛
- رسالة «فاتورة رصيد إضافي» في قوالب البريد.

والقرارات من [FIGMA_READINESS_PLAN.md](../design-audit/FIGMA_READINESS_PLAN.md) §25.

**النطاق:** `scs-platform` و`scs-ops-console`. شراء العيادة بنفسها يأتي مع تطوير تطبيق العيادة، لكن البيانات تحفظ المصدر `purchase` من الآن.

## القواعد
- **الصلاحية حتى نهاية الشهر الميلادي** الذي أُضيف فيه الرصيد، بتوقيت المنصة (Africa/Cairo). ما لا يُستهلك يسقط.
- **الميزات المقيسة:** `message_credits` و`ai_xray_analysis` و`ai_voice_notes` و`teleconsult_minutes`.
  - تضيف الهجرة `teleconsult` (switch) و`teleconsult_minutes` (limit، الوحدة «دقيقة/شهر»، min / mo) إلى الكتالوج، وحالتهما `planned`، كما في [CLINIC_TELECONSULT_PLAN.md](CLINIC_TELECONSULT_PLAN.md) §2 و§4.
  - لا يُضاف رصيد لميزة غير مفعّلة في باقة العيادة.
- **مجانًا:**
  - يعمل فورًا.
  - السبب مطلوب (3–500 حرف).
  - الكمية مضاعف لخطوة الباقة إن كان للباقة سعر وحدة للميزة، وإلا فأي عدد صحيح موجب.
- **بفاتورة:**
  - تشترط سعر وحدة للميزة في الباقة. بدونه: `TOPUP_NOT_SOLD`، والإضافة مجانية فقط.
  - الكمية مضاعف للخطوة.
  - المبلغ: الصافي = الكمية × سعر الوحدة، والضريبة فوق الصافي (`addVat`، القرار أ٩).
  - فاتورة `addon` مستحقة بنهاية الشهر نفسه، وتُنشأ برابط فوري، والرصيد «بانتظار الدفع».
  - يصير نشطًا حين تُسوّى الفاتورة عبر فوري (`settleInvoice`)، ولا يُعلَّم مدفوعًا بغير فوري (Q13).
  - فاتورة إضافة مفتوحة واحدة لكل ميزة لكل عيادة: `TOPUP_INVOICE_OPEN`.
- **السحب:**
  - للرصيد النشط وحده، بسبب مطلوب.
  - لا استرداد آليًا؛ الاسترداد من تبويب الدفعات.
  - لا يُعاد ما استُهلك.
- **إلغاء فاتورة الإضافة:** مسار الإلغاء القائم (`voidInvoice`) يجعل رصيدها «ملغى».
- **نهاية الشهر** (مهمة دورية بنمط `subscription-renewal-reminders`):
  - الرصيد النشط المنتهي يصير «منتهيًا».
  - الرصيد بانتظار الدفع تُلغى فاتورته آليًا (إلغاء نظامي بلا مشغّل، يُلغي طلبات فوري أولًا)، ويصير «ملغى».
- **فاتورة الإضافة لا تؤخر الإيقاف الآلي:** `subscription-enforcement` يتجاهل محاولات فوري الحيّة إلا لفواتير الاشتراك (`renewal` و`new_subscription`).
- **تسجيل دفع فاتورة الإضافة:** يُسجَّل في النشاط برمز خاص به، لا `subscription_paid`.

## البيانات (هجرة واحدة: `YYYYMMDDHHMMSS_quota_topups`)
1. **`plan_extra_units`** (عام، بلا RLS، بمنح القراءة والكتابة كجدول `plan_features`):
   - `plan_id` و`feature_key` مفتاح مركّب؛
   - `unit_price_egp numeric(10,2) > 0`؛
   - `step int >= 1`.
2. **`tenant_quota_topups`** (جدول مستأجر: RLS مفعّل ومفروض + سياسة `tenant_isolation` + منح `scs_app`/`scs_admin` كما في `20260918100000_renewal_reminders`، ويجتاز `prisma/check-rls.sql`):
   - `id`، `tenant_id`، `feature_key`، و`quantity int > 0`.
   - `source` ∈ {`free`,`invoice`,`purchase`}.
   - `status` ∈ {`active`,`awaiting_payment`,`expired`,`revoked`,`cancelled`}.
   - `valid_until timestamptz`: نهاية الشهر بتوقيت القاهرة.
   - `invoice_id` (nullable).
   - `reason` (مطلوب للمجاني) و`note`.
   - `added_by_operator_id` (nullable).
   - `activated_at` و`revoked_at` و`revoked_by_operator_id` و`revoke_reason` و`cancelled_at`.
   - `created_at` و`updated_at`.
   - فهرس فريد جزئي على (`tenant_id`, `feature_key`) حيث `status = 'awaiting_payment'`.
3. **الصلاحية `clinics.topups`** («إضافة رصيد إضافي للعيادات» / Add Extra Quota to Clinics): تُمنح لـ`super_admin` ولكل دور يملك كل الصلاحيات، على نمط `20260918040000`.
4. **توسيع قيد `subscription_history.action`:**
   - `topup_granted` (مجاني)؛
   - `topup_invoiced`؛
   - `topup_activated` (دُفعت الفاتورة)؛
   - `topup_revoked`؛
   - `topup_cancelled`.
5. **فئة بريد لفاتورة الإضافة** إن لم تكفِ فئة الفوترة القائمة، مع توسيع قيد `outbound_messages.category` عند الحاجة.

## الواجهة البرمجية
كل المسارات بنمط `@Public() @UseGuards(OpsJwtAuthGuard, OpsPermissionsGuard) @RequirePermission() @Audit()`، وتُضاف رموز التدقيق إلى `ops-audit.catalog.ts` و`report-labels.ts`.

- **`GET /ops/clinics/:id/topups`** (`clinics.view`) ← `{ rows: TopupRow[], features: TopupFeatureOption[] }`.
  - الصفوف: رصيد الشهر الحالي كله، ثم منتهي الشهر السابق وملغاه ومسحوبه، الأحدث أولًا.
  - `TopupRow`:

    ```
    { id, featureKey, featureNameAr, featureNameEn, unitAr, unitEn, quantity,
      status, validUntil|null, source, reason|null,
      invoice: { id, number, status, amount }|null,
      addedBy: { id, name }|null, createdAt, activatedAt|null,
      revokedAt|null, revokeReason|null, cancelledAt|null }
    ```

  - `TopupFeatureOption`:

    ```
    { key, nameAr, nameEn, unitAr, unitEn, planLimit|null, unitPriceEgp|null, step }
    ```

    الميزات المقيسة المفعّلة في الباقة وحدها.
- **`POST /ops/clinics/:id/topups`** (`clinics.topups`، `@Audit('topup_added')`)
  - الطلب: `{ featureKey, quantity, charge: 'free'|'invoice', reason?, note? }`.
  - الرد: `{ topup: TopupRow, invoice?: { id, number, amount, vatPercent, dueAt, paymentUrl|null, paymentLinkError|null } }`.
- **`POST /ops/clinics/:id/topups/:topupId/revoke`** (`clinics.topups`، `@Audit('topup_revoked')`) ← الطلب `{ reason }`، والرد `TopupRow`.
- **إلغاء فاتورة الإضافة:** عبر `POST /ops/invoices/:id/void` القائم (`clinics.payments`).
- **رموز الخطأ:** `TOPUP_FEATURE_NOT_METERED`، و`TOPUP_FEATURE_NOT_IN_PLAN`، و`TOPUP_NOT_SOLD`، و`TOPUP_STEP`، و`TOPUP_INVOICE_OPEN`، و`TOPUP_NOT_ACTIVE`.
- **الباقات:**
  - `PlanBodyDto.extraUnits?: { key, unitPriceEgp, step }[]`: ميزة مقيسة من نوع limit مفعّلة في الباقة، وسعر > 0، وخطوة ≥ 1؛ تُستبدل كلها عند الحفظ.
  - تفاصيل الباقة تُرجع `extraUnits`.
- **تفاصيل العيادة:** `planFeatures` يضيف `extra` لكل ميزة مقيسة، وهو مجموع الرصيد النشط هذا الشهر.

## الكونسول (`scs-ops-console`)
- **بطاقة «الرصيد الإضافي»** بعد «مستخدمو العيادة» في النظرة العامة:
  - الأعمدة: الميزة · الكمية · الحالة · يسري حتى · المصدر · أضافه.
  - «+ إضافة رصيد» لحاملي `clinics.topups`.
  - حالة فارغة: «لا رصيد إضافي هذا الشهر».
- **قائمة «⋯» حسب الحالة**، ولا قائمة ولا زر لمن لا يملك الصلاحية:
  - **نشط (مجاني):** سجل التدقيق، ثم «سحب الرصيد…» بعد فاصل.
  - **نشط (مدفوع):** عرض الفاتورة، وسجل التدقيق، ثم «سحب الرصيد…».
  - **بانتظار الدفع:** عرض الفاتورة، ونسخ رابط الدفع، ثم «إلغاء الفاتورة…» لحاملي `clinics.payments`.
  - **منتهٍ:** عرض الفاتورة للمدفوع وحده.
  - **مسحوب:** سجل التدقيق.
  - **ملغى:** عرض الفاتورة، وسجل التدقيق.
- **نافذة الإضافة:**
  - الميزة مع حدّ الباقة، والكمية مع تلميح الخطوة، وطريقة الاحتساب (مجانًا / بفاتورة؛ الفاتورة معطّلة مع سبب إن لم يكن للباقة سعر وحدة)، والسبب للمجاني، والملاحظة للفاتورة.
  - ملخص: سعر الوحدة × الكمية، والضريبة، والإجمالي.
  - لافتة القاعدة.
  - تحقق عند الإرسال.
- **نوافذ أخرى:** تأكيد السحب بسبب مطلوب، و«صدرت الفاتورة» (الرقم، والمبلغ، والاستحقاق، ورابط فوري للنسخ، وإعادة الإرسال).
- **محرّر الباقة:** «سعر الوحدة الإضافية (ج.م)» و«الخطوة» لكل ميزة مقيسة مفعّلة. وفي تفاصيل الباقة بطاقة «الوحدات الإضافية».
- **كتالوج الصلاحيات:** `clinics.topups` في مجموعة العيادات، مع تحديث `format.test.ts`.
- **الترجمة والسجلات:** مفاتيح عربية وإنجليزية، وصياغة التدقيق والنشاط.

## الاختبارات
- **الخادم:**
  - الخدمة: مجاني، وبفاتورة، والسحب، وكل رموز الخطأ، وحساب نهاية الشهر.
  - الفوترة: فرع `addon` في التسوية، وإلغاء الفاتورة يُلغي الرصيد، وتجاهل الإيقاف لفواتير الإضافة.
  - مهمة نهاية الشهر.
  - تحقق `extraUnits` في الباقات.
  - تغطية المسارات، وكتالوج الصلاحيات.
- **الكونسول:**
  - البطاقة حسب الحالة والصلاحية.
  - حساب الملخص والتحقق في نافذة الإضافة.
  - قائمة الصلاحيات، وتطابق الترجمة.

## ما نُفّذ (28 سبتمبر 2026)
**الهجرة:** `20260928120000_quota_topups`.

**الخادم:**
- وحدة `src/ops-topups`.
- في `subscription-billing`:
  - `issueTopupInvoice`، وفرع `addon` في التسوية؛
  - إلغاء الفاتورة يُلغي رصيدها، وإلغاء نظامي بلا مشغّل؛
  - مهمة نهاية الشهر `quota-topups-month-end`؛
  - الإيقاف الآلي يتجاهل محاولات فوري لغير فواتير الاشتراك.
- `extraUnits` في الباقات، و`extra` في ميزات باقة العيادة.
- بريد فاتورة الإضافة، ورموز التدقيق والنشاط.

**الكونسول:**
- بطاقة «الرصيد الإضافي» بقوائمها حسب الحالة.
- نوافذ الإضافة والسحب و«صدرت الفاتورة».
- أسعار الوحدات في محرّر الباقة، وبطاقتها في تفاصيل الباقة.
- الصلاحية، والترجمة، وصياغة التدقيق والنشاط.

**قرارات أثناء التنفيذ:**
- **البريد والرابط:**
  - يُرسل بريد فاتورة الإضافة لحظة إصدارها إن أُنشئ رابط فوري. يصل اليوم إلى مالك العيادة وحده، ويُرجع الرد `emailedTo` (0 أو 1).
  - «إعادة إرسال الرابط» و«نسخ رابط الدفع» و«إلغاء الفاتورة» عبر مسارات الفواتير القائمة، فتتطلب `clinics.payments`.
- **صلاحيات إضافية تفرضها مسارات قائمة:**
  - «عرض في سجل التدقيق» يتطلب `security.manage` (مسار السجل).
  - «عرض الفاتورة» يتطلب `reports.financial` (صفحة الفاتورة).
- **الضريبة:** قائمة الرصيد تُرجع `vatPercent`، فتعرض نافذة الإضافة الصافي والضريبة والإجمالي كما ستحسبها الفاتورة.
- **مهمة نهاية الشهر:** تعمل كل 15 دقيقة، وتُلغي حتى 100 فاتورة في المرة.
  - مال يصل بعد نهاية الشهر وقبل الإلغاء يُسجَّل مالًا غير مخصّص، ويُردّ من تبويب الدفعات، ولا يُفعَّل الرصيد.
- **أسعار الوحدات:** إغفال `extraUnits` في حفظ الباقة يُبقي الأسعار، وإرسال قائمة ولو فارغة يستبدلها كلها. إيقاف ميزة يحذف سعرها.
- **لم يُعالج:** فاتورة إضافة مفتوحة لا تمنع تغيير الباقة، فتُدفع بسعر الباقة القديمة.

**التحقق:**

- الكونسول: 78 ملفًا و707 اختبارات تنجح، والفحص النوعي والتدقيق والتنسيق والبناء نظيفة.
